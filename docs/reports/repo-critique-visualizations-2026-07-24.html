A dotfiles repo that is 0.4% dotfiles

The name says shell config; the tree says AI-coding research lab. The actual dotfiles (home-config/) are 215 lines of a 58,549-line repository — the rest is an agent-tooling workshop: 12 skills, 9 commands, a parameter wiki drafted in twelve parallel taxonomies, and 33k lines of committed session leftovers. None of that is bad work. But the repo has stopped being what it claims to be, and some of the weight is pure ballast.

finding 05 · recursion

The repo is starting to critique itself for a living

8 of 62 commit subjects — 13% — contain the word "critique". The repo carries five critique documents of its own parameter wiki, a repo-wide critique report, and an agent-swarm critique sampled 10 times. Nearly half of all docs commits are the repo examining itself.

Self-review is healthy. But critique reports are only worth their weight when their findings get executed and then deleted — otherwise they accumulate as one more thing to maintain. PRs #5, #6, and #7 added three near-identical wiki critiques in one day; #8 merged them into a task list; the tasks are still mostly open.

Full disclosure: this page is a critique of a repo that contains critiques of itself, one of which critiques the other critiques. You are now four levels deep. The fix list below is designed to be executed and then thrown away — please oblige.

finding 06 · runtime hazards

install.sh has teeth

Not chartable, so here it is as a review. Severity reflects what happens to a user who follows the README on a fresh machine.

▲ critical
Sourcing + exit 1 kills the user's terminal. The README's install command is source install.sh, but the script has six exit 1 paths (install.sh:23–41). When sourced, any of them terminates the calling shell — an unsupported $SHELL closes your terminal window as its error message.
use return when sourced (detectable via $ZSH_EVAL_CONTEXT / BASH_SOURCE), or change the README to ./install.sh.
◆ serious
The shell whitelist rejects Ubuntu's own zsh. Detection compares $SHELL against four hardcoded paths (install.sh:33–42) — /bin/zsh, /opt/homebrew/bin/zsh, /bin/bash, /opt/homebrew/bin/bash. On Ubuntu, the platform the script explicitly supports, zsh installs to /usr/bin/zsh → "unsupported shell" → (because you sourced it) your terminal exits.
match on case "$(basename "$SHELL")" instead of full paths.
◆ serious
Home dotfiles are overwritten with no backup. cp -af home-config/. "$HOME"/ (install.sh:110) silently clobbers an existing .vimrc, .tmux.conf, and Cursor MCP config. The sync script has backup/unlink machinery; the install path bypasses it.
back up to ~/.dotfiles-backup-<date>/ before the copy, or route through sync-coding-tools' backup logic.
● warning
apt calls block or fail on common setups. sudo apt-get install tilix (install.sh:67) has no -y, so unattended runs hang at the prompt; apt install --update curl (install.sh:54) needs a recent apt and errors on Ubuntu 22.04.
sudo apt-get update && sudo apt-get install -y …
● warning
Installer piped into an arbitrary shell. curl -fsSL https://ollama.com/install.sh | $SHELL (install.sh:147) runs a bash-targeted installer under whatever the login shell is — under zsh, bashisms in the installer are luck, not contract.
pipe to sh explicitly, and prefer download-then-run for auditability.

credit where due

What's genuinely good here

  • sync-coding-tools.sh is real engineering. One 420-line source of truth for copy and symlink modes, with --dry-run, status, an audit log, and a reversible --unlink — most dotfiles repos never get this right.
  • The Makefile is self-documenting. make help is generated from ## comments, and the Makefile explicitly refuses to duplicate logic that belongs to the script.
  • Conventional commits, consistently. 52 of 62 subjects parse cleanly as type(scope): subject — that's how this report could chart the history at all.
  • Idempotent shell wiring. The managed block in ~/.zshrc is guarded by a marker comment grep — re-running install doesn't stack duplicate source lines.
  • Multi-tool plugin layout is clever. One canonical ai-coding/commands + skills, re-exposed to Cursor and Claude through relative symlinks and per-tool manifests, instead of three diverging copies.
  • The .gitignore explains itself. Each ignore rule carries its rationale as a comment.

order of operations

Six fixes, highest leverage first

  1. Defang install.sh. Fix the source/exit trap, basename-match the shell, and back up before cp -af. This is the only finding that damages a user rather than the repo.
  2. Delete the leftovers. Remove ai-coding/samples/misc-leftovers/ (history keeps it) — the repo halves in a single commit. Add a samples policy: excerpts in, raw session dumps out.
  3. Declare a wiki winner. Pick one taxonomy as canonical in parameters/generated/, move the runners-up to a branch or docs/reports/, and delete the 8 byte-identical copies now regardless.
  4. Rewrite the README for what the repo is. Two sections: "dotfiles" (install, sync) and "ai-coding" (the actual center of mass — skills, commands, plugin marketplace). The 15-line README documents 3% of the repo.
  5. Close the critique loop. Burn down parameters/TASKS.md, then delete the executed critique reports instead of archiving new ones alongside them.
  6. Adopt shfmt + shellcheck in CI. shfmt is already in the Brewfile; there is no CI at all. A 10-line workflow linting the six shell scripts would have caught most of finding 06.
