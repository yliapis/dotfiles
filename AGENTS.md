# AGENTS.md

## Cursor Cloud specific instructions

Dotfiles + AI-coding tooling repo. Shell scripts install dotfiles and mirror
`ai-coding/` commands + skills into the Cursor, Claude, and OpenCode home
locations.

Cloud agent setup is defined in `.cursor/environment.json`, which runs the
provider-agnostic `.cursor/scripts/cloud-agent-bootstrap.sh` at VM boot to
apt-install `zsh`, `rsync`, and `shellcheck` so the repo's scripts are
runnable. Homebrew, the Brewfile, and ollama are intentionally not installed
in cloud (headless VM; slow boots); run `./install.sh` manually only if a task
needs them. Run `make help` for details on sync and other targets.

## Project command/skill mirrors

Repo-root `.cursor/{commands,skills}/`, `.claude/{commands,skills}/`, and
`.opencode/{commands,skills}/` are flattened per-item mirrors of
`ai-coding/plugins/*/{commands,skills}`, generated by
`scripts/sync-project-mirrors.sh`. They hold real copies, not symlinks: these
tools index the mirror directories to build the skill list they offer the
agent, and that indexing does not follow symlinks, so a symlinked skill stays
readable by path but never auto-attaches.

`ai-coding/plugins/` stays the only place to edit a command or skill. After
adding, renaming, or removing one, regenerate all six mirrors (entries whose
source is gone are pruned) and confirm they match:

```sh
make mirrors
make mirrors-check
```

`make mirrors-symlink` swaps the mirrors back to symlinks for a working copy
where live edits matter more than auto-attach. The script is POSIX `sh` and
needs neither zsh nor rsync, so it works on a VM whose bootstrap failed.

## Skills

The mirrors let every tool auto-attach these skills, so normally there is
nothing to do. When a session starts without them, enumerate the catalog
before picking an approach and read the ones that match:

```sh
grep -H '^description:' .cursor/skills/*/SKILL.md
```

See `README.md` for more information.
